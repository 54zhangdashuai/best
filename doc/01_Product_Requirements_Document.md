# 产品需求文档 (PRD)

**项目名称**：年会实时投票系统
**版本**：V1.0
**日期**：2026-01-15

## 1. 项目背景
当前的年会投票系统是一个纯前端演示版本，无法满足真实的多人并发投票需求。我们需要将其升级为一个具备前后端交互、支持多端访问、可部署在云服务器上的真实生产系统。

## 2. 目标用户
*   **普通员工**：使用手机扫码参与投票。
*   **现场观众**：通过会场大屏查看实时排名。
*   **管理员**：通过后台管理系统控制节目单和重置数据。

## 3. 核心业务流程
1.  **准备阶段**：管理员登录后台，配置节目列表，清空测试数据。
2.  **投票倒计时阶段**：管理员设置倒计时时长并点击“开始投票”，倒计时同步出现在投票端与大屏端。
3.  **投票阶段**：员工扫码进入投票页，选择心仪节目投票，边框呼吸效果随倒计时推进逐步加速并变色。
4.  **展示阶段**：大屏实时滚动更新各节目票数，倒计时显示当前剩余时间。
5.  **结束阶段**：倒计时归零，投票截止，大屏定格。

## 4. 详细需求说明

### 4.1 移动端 - 投票页 (Client-Side)
*   **功能描述**：员工参与投票的界面。
*   **页面元素**：
    *   复用原有 `VotingView` 的卡片设计。
    *   节目列表（卡片式布局）：包含节目名称、表演者（可选）、当前票数（可选，或仅大屏显示）。
    *   **选择模式**：支持多选（Checkbox）。
    *   投票按钮：底部统一提交按钮。
*   **交互逻辑**：
    *   **规则校验**：用户选择节目数量必须符合管理员设置的要求（例如：必须选 3 个）。如果不满足，点击提交时提示“请选择 X 个节目”。
    *   点击“提交投票”：发送包含所有选中节目ID的请求至后端。
    *   成功反馈：弹出“投票成功”提示。
    *   失败反馈：如已投过票，提示“每人仅限一票”。
    *   **倒计时显示**：右上角显示剩余时间，单位为秒，格式为 `mm:ss`。
    *   **边框呼吸效果**：页面最外围显示渐变呼吸边框，随倒计时推进逐步加速，颜色从绿色 → 青色 → 黄色 → 橙色 → 红色渐变。
*   **约束**：
    *   基于 IP 或 Cookie 限制重复投票。
    *   界面需适配主流手机屏幕（响应式）。

### 4.2 大屏端 - 结果页 (Screen-Side)
*   **功能描述**：放置在现场大屏幕，展示实时数据。
*   **页面元素**：
    *   动态排行榜：按票数从高到低自动排序（或固定顺序显示票数）。
    *   可视化图表：柱状图或条形图。
    *   总票数统计（可选）。
*   **交互逻辑**：
    *   **自动刷新**：每 2 秒自动获取最新数据。
    *   **动画效果**：票数变化时有数字滚动或进度条增长动画。
    *   **倒计时显示**：右上角同步显示剩余时间，归零后维持 00:00 状态。
    *   **边框呼吸效果**：与投票端一致，倒计时末尾阶段动画明显加速并转向红色渐变。

### 4.3 管理端 - 后台 (Admin-Side)
*   **功能描述**：控制系统数据。
*   **安全验证**：
    *   访问拦截：未登录用户无法看到管理界面。
    *   登录验证：输入固定密码 `54zds`。
*   **功能模块**：
    *   **节目管理**：
        *   列表展示：查看当前所有节目。
        *   新增节目：输入名称。
        *   删除节目：移除废弃节目。
    *   **全局控制**：
        *   **投票规则配置**：设置单次投票必须选择的节目数量（例如：每人必须投 3 票）。
        *   **重置数据**：危险操作，需二次确认。清空所有投票记录，票数归零。
        *   **倒计时控制**：设置倒计时时长（秒/分钟），点击“开始投票”触发倒计时同步下发到前端。

## 5. 非功能需求
*   **性能**：支持至少 200-500 并发请求（SQLite + Node.js 足以应对）。
*   **部署**：支持 Docker 一键部署，运行于 Ubuntu 22.04 LTS。
*   **兼容性**：移动端兼容 iOS/Android 主流浏览器（Chrome/Safari/WeChat Webview）。
*   **可维护性**：代码结构清晰，前后端分离。
