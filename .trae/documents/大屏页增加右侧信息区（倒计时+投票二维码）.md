## 目标
- 大屏页（16:9）改为“左主榜单 + 右信息区”两列布局。
- 右侧信息区展示：投票倒计时（mm:ss）+ 投票页二维码图片（photo/vote.png）+ 简短提示（可选：投票链接）。
- 不遮挡主内容，不改变投票页/管理页现有视觉。

## 页面结构改造（方案二落地）
- 将大屏页的根布局从单列容器改为两列：
  - 左侧主区域：排行榜 + 统计条 + 动画（现有内容）
  - 右侧信息区：固定宽度（建议 320–380px），垂直排版
- 布局实现建议：CSS Grid 或 Flex（优先 Grid），例如：`grid-cols-[1fr_360px]`，整体 `min-h-screen`。
- 视觉细节：
  - 右侧信息区使用浅色卡片背景、圆角、轻阴影；保持与当前 Tailwind 风格一致。
  - 二维码展示为正方形，限制最大宽高（例如 240–280px），避免过大抢占注意力。

## 倒计时展示逻辑（避免 2s 跳变）
- 大屏当前每 2 秒轮询 `/api/programs` 拿到 `config`。
- 倒计时不使用 `config.remaining_seconds`（它可能 2s 更新），改用：
  - 保存 `config.countdown_end_at` 到 state
  - 本地用 `setInterval(250ms)` + `Date.now()` 计算 `Math.ceil((endAt - now)/1000)`，显示为 `mm:ss`
- 当倒计时结束：右侧倒计时显示 `00:00`（可选：显示“投票已结束”）

## 二维码图片接入方式
- 不移动文件位置：直接在大屏组件中通过 Vite 静态资源 import 引入 `photo/vote.png`，保证 Docker build 后仍可访问。
- 右侧信息区下方加一行引导文案：如“扫码进入投票页”。
- 可选：显示投票链接文本，取 `window.location.origin + '/vote'`（便于现场人工输入/备用）。

## 路由兼容（/screen）
- 当前路由已有 `/leaderboard`，文档与口径已转向 `/screen`。
- 增加 `/screen` 路由作为 `/leaderboard` 的别名，避免现场使用新路径时 404。

## 与现有全局倒计时 UI 的关系
- 现在全局 Layout 会在大屏路由右上角渲染固定倒计时。
- 改造后：在大屏路由下关闭该固定倒计时（避免与右侧信息区重复/遮挡）；投票页/管理页仍保持原样。
